**仙本那珊瑚礁气候预警台** — AI4Climate 全球青年气候解决方案挑战赛参赛作品

> 参赛方向：**04 沙巴仙本那珊瑚礁气候韧性** ｜ 参赛形式：**组队参赛** ｜ 团队名与成员：〔待填〕
> 站点：马来西亚沙巴州仙本那 Semporna（4.6°N, 118.7°E）

## 这是什么

用全公开的海洋与气象数据，为仙本那珊瑚礁做一条**可复现的数据流水线**，把大浪 / 强降水径流 / 风暴增水三类超阈值事件合成一个 0–1 的**复合灾害危险指数**（海水升温单列为热压力日），再用岭回归预测未来 **1–14 天**，并在**单文件离线界面**上把预报翻译成潜水运营商 / 珊瑚修复队 / 度假村与政府三类人能直接执行的动作。

## 立刻看效果

**方式一（最简单）**：双击项目根目录的 **`启动预览.bat`** —— 它会自动启动本地服务器并在 2 秒后打开浏览器，看完关掉那个窗口就停止服务。

**方式二（不想开服务）**：直接双击 [demo/index.html](demo/index.html)，离线也能看全部内容。

**方式三（服务器地址）**：<http://127.0.0.1:8788/> —— 根路径就是这个唯一页面（也可以直接双击 [demo/index.html](demo/index.html)）。

### 为什么只有一个页面

项目**只有一个成品页面** [demo/index.html](demo/index.html)：全部数字、表格与 4 张图都由 [pipeline/build_static.py](pipeline/build_static.py) 在 Python 侧预先算好并写成 SVG/HTML，页面里**一个 `<script>` 都没有**。

这样做的原因很实际：不少预览窗口（沙箱 iframe、纯文件预览、禁用 JS 的阅读器）**不执行 JavaScript**，靠脚本现场绘图的页面在那里会显示成一片空白 —— 这正是之前“打开后什么都没有”的原因。改成预渲染后，双击、预览、投稿附件、评审机器上都能看到完整内容，离线也不影响。

> 早期为了对比，曾另做过一版“浏览器现场绘图”的交互版，现已移出本项目（备份在 `珊瑚哨兵\备份\界面_交互版备份\`），项目里只保留这一个页面。

## 核心结果（样本外，扩展窗前推交叉验证）

危险指数回归（岭回归 **66 个特征** = 滚动统计 + 灾害记忆 + 季节项 + 当日原始变量水平；收缩强度 λ 由每一折训练窗**内部的交叉验证**挑选，从不接触测试段）对比三个业务可行基线：

| 时效 | 模型 RMSE | 持续预报 | 气候平均 | 常数均值 | 排序 AUC（模型 / 持续） | 相对持续预报误差下降 |
|---|---|---|---|---|---|---|
| 1 天 | **0.1406** | 0.1776 | 0.2057 | 0.1644 | **0.795 / 0.587** | **20.8%** |
| 3 天 | **0.1603** | 0.1935 | 0.2056 | 0.1637 | **0.665 / 0.429** | **17.2%** |
| 7 天 | **0.1624** | 0.1919 | 0.2045 | 0.1635 | **0.600 / 0.433** | **15.4%** |
| 14 天 | **0.1615** | 0.1772 | 0.2028 | 0.1638 | **0.615 / 0.583** | **8.9%** |

**我们把最不利的一条基线也放上桌**：危险指数有 72.3% 的日取值为 0，因此"永远预报训练期平均值"的**常数均值**基线极难被超过——模型在 3 / 7 / 14 天只比它低 0.0034 / 0.0011 / 0.0023（0.1603 / 0.1624 / 0.1615 对 0.1637 / 0.1635 / 0.1638），属**噪声量级**；只有 1 天的优势是实的——相对持续预报低 20.8%（0.1406 对 0.1776）、相对常数均值低 14.5%（0.1406 对 0.1644）。模型的真实价值在**排序**：把未来第 h 天"至少一项驱动超阈值"的日子排到前面的 AUC 为 0.795 / 0.665 / 0.600 / 0.615，全时效高于持续预报（0.587 / 0.429 / 0.433 / 0.583）与气候平均（0.443 / 0.439 / 0.441 / 0.461）；14 天与持续预报只差 0.032，优势不宽，也如实标出。

**把预报朝训练期均值收缩，四个时效都能压过常数均值**：收缩系数由训练段内部的交叉验证挑选（`pipeline/blend_audit.py`，只看训练段，不接触测试段），校准后 RMSE = **0.1406 / 0.1586 / 0.1624 / 0.1613**（收缩系数 β* = 0.9 / 0.7 / 0.9 / 0.8），对应常数均值 0.1644 / 0.1637 / 0.1635 / 0.1638；1 天赢 **14.48%**，3 / 7 / 14 天只赢 3.11% / 0.70% / **1.54%**（即 0.0011–0.0051）。正的线性缩放不改排序，AUC 基本不变；因为这点优势属噪声量级、收缩还会抹平日间差异，成品页部署的仍是满幅预报，收缩只作 RMSE 口径的精度上限对照。

**λ 不再是一个固定常数**：报告表里每一折的 λ 都由该折训练窗**内部的交叉验证**挑选（`pipeline/model.py` 的 `inner_lambda`，只在训练段里切 70% / 85% 两段，从不接触测试段）；成品页当日预报取逐折内窗 CV 挑选值的众数（50 / 100 / 800 / 3200 各并列 2 次，取最小）= λ = 50。在同一套 3 折协议上扫 λ ∈ [5, 20, 50, 100, 200, 400]，RMSE 最优的 λ 随时效右移（1 天 50：**0.1402**；3 天 50：0.1588；7 / 14 天 1600：0.1619 / 0.1624），λ = 400 时 14 天 RMSE 是 **0.1624**（已低于常数均值的 0.1638），3 天排序 AUC 也从 λ = 5 的 0.665 升到 **0.676**——在这个区间里 RMSE 与排序并不冲突；四档平均排序 AUC 在 λ = 50–200 达峰 **0.679**；从 λ = 5 加到 6400，平均 AUC 只在 0.659–0.679 之间移动——是平台不是尖峰。完整网格见 docs/02 第 3.5 节与成品页的 λ 敏感性表。

**同时如实保留负面结果**：二元分类预警（未来 7 天是否成灾）样本外 **AUC = 0.495**（≈随机），且除 1 天外在 3/7/14 天**全面输给朴素持续预报**（复合灾害强成簇）。产品因此弃用分类器。

**跨站点验证（回应「单站点不算数」）**：同一套代码、同一套定义在三个珊瑚礁站点各跑一遍——仙本那（4.60N / 118.70E）、印尼 Bunaken（1.62N / 125.20E）、帕劳岩岛（7.30N / 134.50E），各 1,404 天，阈值全部按各站自身分位数重算（不搬运本站参数）。结果：**12 个格（三站 × 四个时效）里有 11 格的排序 AUC 高于持续预报**（1 天 0.779 / 0.801 / 0.742，3 天 0.611 / 0.700 / 0.585，7 天 0.570 / 0.641 / 0.551，14 天 0.580 / 0.656 / 0.554，对持续预报 0.600 / 0.627 / 0.621、0.443 / 0.476 / 0.485、0.436 / 0.485 / 0.439、0.584 / 0.603 / 0.485）；唯一例外是仙本那 14 天，模型 0.580 对持续预报 0.584（低 0.004）——我们不为了「全胜」去挑窗口，如实标注；RMSE 对持续预报三站全胜，对常数均值 Bunaken 与帕劳四个时效全胜、仙本那 3 个时效胜出（Bunaken 0.1316 / 0.1480 / 0.1524 / 0.1492 对 0.1582 / 0.1579 / 0.1577 / 0.1567；帕劳 0.1554 / 0.1674 / 0.1682 / 0.1656 对 0.1686 / 0.1682 / 0.1684 / 0.1660）——再次说明在 73% 零值的指数上 RMSE 不是好尺子。阈值从 p85 收紧到 p95，复合灾害日从 6% 到 8% 降到约 1%，而模型对持续预报的优势在三档、三站都保持。换站点时必须用新站点自己的记录重建阈值与基线。
**白化识别与保护优先级也同样跨站复用**（31 天滑动季节气候态与 p90 判据不变，阈值与事件全部按各站记录重建）：三站分别识别到 12 次 / 91 天、9 次 / 96 天、11 次 / 93 天，最强一次分别是 2026-09-24 起 13 天（2 级）、2024-08-10 起 33 天（2 级）、2025-03-03 起 17 天（1 级）。

**不确定区间是标定过的，不是拍脑袋**：用与成品页完全相同的 3 折设置检查样本外残差——±1×RMSE 的实际覆盖率是 69.5%–76.0%（高斯名义值 68.3%，说明残差近似正态），要覆盖 80% 只需 1.18–1.28 倍 RMSE。成品页的区间因此改成**经验 80% 区间**，倍数逐时效取自 `data/processed/interval_audit.json`（由 `pipeline/interval_audit.py` 生成）。驱动本身的误差仍未单独传播，这一条照旧披露。
## 数据

- Open-Meteo Marine（逐小时海洋：海温/波高/风浪/潮位/海流）+ Open-Meteo Archive ERA5（逐日气象），**2022-11-01 至 2026-10-16，1,446 天**，全部公开免费 API，可一键刷新到最新一天。
- 阈值取**本站记录期分位数**（浪 p90 = 0.40 m，雨 p90 = 15.6 mm，增水 p90 = 0.033 m，日均海温 p90 = 30.667 °C），保证方法可迁移到其他站点；记录期每延长一天，阈值会有小数点后第三位的轻微漂移，属预期。
- **官方交叉印证**：NOAA Coral Reef Watch 5 km v3.1 公开汇总 CSV（1985-03-25 至 2026-10-13，15,178 天）与珊瑚大三角区域灾害等级图已抓取到 [data/external/noaa_crw/](data/external/noaa_crw/)，并作为官方对照面板画进成品页：官方记录同样把 **2024 年**列为最严重年份（全球白化预警区占比峰值 15.75%、太平洋 20.65%），与本站该年复合灾害日最多（15 天）方向一致。
- **区域站点级对照（比流域占比更近一层）**：NOAA CRW 的「Sabah, Malaysia」区域虚拟站点就是同一片沙巴海域的 5 km 逐日产品（SST / 热斑 / DHW / 预警级别），已抓取到 [data/external/noaa_crw/vs_sabah_daily.csv](data/external/noaa_crw/vs_sabah_daily.csv)，并由 [pipeline/fetch_noaa_vs.py](pipeline/fetch_noaa_vs.py) 在每日刷新链里自动更新（抓不到就沿用上一次，不让链条中断）。1,409 天重叠期内：**本站 13 次热浪有 13 次落在官方预警期内**，本站日均海温与官方热斑像素 SST 平均只差 **0.013 °C（r = 0.717）**；官方站点 2026-10-14 的 DHW = 14.01、预警级别 4（Alert Level 2 最高档），而本项目因基线偏严自算 DHW = 0 —— 两个口径的差别与原因都写在页面和文档里。换一个官方站点（帕劳）独立复核：1,402 天重叠期内偏差 0.061 °C、r = 0.921，p90 热日全部落在官方预警期内；布纳肯在官方虚拟站点列表里没有对应文件（HTTP 404），所以官方逐日对照覆盖 2 个站点。
- 官方 NetCDF 点位时间序列在本环境仍不可得（ERDDAP 数据通路 302 到不可达主机、本机无 HDF5 读取库），取数命令留档 [data/external/FETCH_NOAA_CRW.sh](data/external/FETCH_NOAA_CRW.sh)，材料中如实披露。

## 数据怎么更新（一键刷新，实测约 30 秒）

成品页是**预渲染的快照**（评审与文件预览环境不执行 JavaScript，动态渲染的页面在那里会一片空白），但它不是死的：

```
双击 更新数据.bat
```

它会调用 [pipeline/refresh.py](pipeline/refresh.py)，依次完成 8 个步骤（含未来驱动预报取数）：

1. [pipeline/fetch_open_meteo.py](pipeline/fetch_open_meteo.py) 从 Open-Meteo 增量抓取到最新一天（按原格式合并回两个原始 CSV，先写 .tmp 再原子替换）；
2. 重算静水位 / 增水残差、三类复合驱动与海温各自的百分位阈值、复合灾害指数；
3. 重算 66 个特征与岭回归（1–14 天，λ 由训练窗内窗 CV 挑选），刷新与持续预报、气候平均、常数均值的对比；
4. [pipeline/fetch_forecast_drivers.py](pipeline/fetch_forecast_drivers.py) 抓未来数值天气预报驱动（浪高 / 海温 / 水位 / 降水），供未来 8 天预报使用；
5. [pipeline/build_dashboard.py](pipeline/build_dashboard.py) 把预报驱动按与历史相同的定义拼进序列，重算滚动特征与逐日复合灾害判定后预测，得到逐日变化的预报；
6. 重新解析 NOAA 官方汇总 CSV；
7. 重新生成 [demo/index.html](demo/index.html)，并跑一遍全量核验（[pipeline/verify_demo.py](pipeline/verify_demo.py)）。

跑完页面顶部的「数据窗口 / 最后更新」会前移一天，所有图表与数字随之刷新。**实测：2026-10-15 → 2026-10-16，约 30 秒（含三个站点与未来驱动预报取数），核验 ALL PASS。**

刷新之后还可以生成一条**可直接发给潜店/修复队的每日中文简报**（这也正是 90 天验证计划里要群发的内容）：

```powershell
& $py tools\paper_forecast.py   # -> data/processed/daily_brief_latest.txt
```

提交前一键自检（重跑流水线 + 全部校验，只给一个结论）：

```powershell
& $py tools\preflight.py            # refresh -> Word 材料 -> 一致性审计 -> 打包 -> 提交包自检 -> 结算器自检；末行 PREFLIGHT ALL PASS
& $py tools\submission_selfcheck.py # 只想单独看材料齐不齐、还剩几处待填
& $py tools\consistency_audit.py    # 只想单独看文档数字能否在 data/processed 里算出来，顺带扫过期数字
```

若想让它每天自动跑，把 `pipeline\refresh.py` 挂到 Windows 任务计划程序即可。本项目提交物本身刻意保持为一个**无需服务器、无 JavaScript 依赖**的静态文件，这样在任何评审环境都能打开。

## 白化识别与保护优先级（2026-10 新增）

除了 NOAA 官方对照，本项目自带本地识别：以本站逐日海温建 31 天滑动季节气候态，按 Hobday 2016/2018 口径识别海洋热浪并分级，全期 **13 次**事件；档位阈值取本站记录自身的分位数，当前处于第 **92.1%** 位（"极高"档）。保护优先级按三站点同一口径重算，仙本那得分 **0.9604** 排第一；未来 8 天按风险上界排序给出可逆施工窗口，热浪结束后 4 到 8 周设为固定样线复测窗口。脚本：[pipeline/bleaching_watch.py](pipeline/bleaching_watch.py)、[pipeline/priority_plan.py](pipeline/priority_plan.py)。 更进一步，识别结果被升级成**学习组件**（[pipeline/bleach_forecast.py](pipeline/bleach_forecast.py)）：用 17 个"当日为止可见"的特征预测「未来 28 天内本站是否出现热浪日」，逻辑回归 + L2、4 折扩展窗前推。正类占比 29.8%，所以主指标用 PR-AUC（平均精度）而不是准确率：**模型 0.364，现行规则 0.311，基准发生率 0.242**（ROC-AUC 0.706、Brier 0.278）。我们同时把反例放上桌：第 3 折规则的 PR-AUC 是 **1.000**，模型只有 0.499；今天两个口径也不一致——档位规则读"极高"（第 92.1% 位），模型给未来 4 周的概率只有 0.202，它们回答的是两个不同问题（过去 84 天积了多少热压力 vs 接下来 4 周还会不会再来一次）。我们还把判断做成了**触发—响应 SOP（7 条）**：分档线、复测日期与施工窗口全部由本站数据自动计算（日常 / 关注 / 触发 48 小时 / 严重 24 小时 / 恢复 0–4 周 / 4–8 周 / 施工窗口选择），谁在什么条件下做什么不再靠临场拍脑袋。事件级对照也补上了：13 次站内热浪只有 **3 / 13 = 23.1%** 与官方太平洋抬升同期（提升 1.35 倍），再次说明区域产品替代不了本地判断。

## 如何运行（完整复现）

```powershell

# 0) 环境：Python 3.12 + numpy（本项目不依赖 sklearn / matplotlib，无额外安装）
$py = "python"   # 若你机器上有 py 启动器，也可写 $py = "py"
```

## 诚实披露（写给评审，也写给用户）

1. 按 NOAA 标准（MMM+1°C）算出的 DHW 在本项目上**恒为 0**，原因是基线取法：官方长期 MMM = 29.4999 °C，而本项目只有 3 年多记录，只能取记录内最暖月实际均值 30.517 °C，阈值因此高过记录内最高海温——不是海温产品偏暖（本站日均海温与官方区域站点热斑 SST 只差 0.013 °C，r = 0.717）。因此本指数是**相对本站历史**的压力指标，不能读作“绝对白化风险为零”；官方区域站点同一时期的 DHW 与预警级别（2026-10-14：DHW 14.01 / Alert Level 2）已并列展示在成品页上。
2. 热压力基线仅 2023 一年（MMM = 30.517 °C），远短于 NOAA 的 1985–1993 标准基线，是**保守下限**。
3. 预报由**数值天气预报驱动**：浪高 / 海温 / 水位取自 Open-Meteo 海洋预报，降水取自其气象预报，按与历史完全相同的定义拼进驱动序列后重算滚动特征、逐日复合灾害判定与记忆特征，因此每天的指数都随预报变化。受海浪与海温预报产品时效限制，驱动预报覆盖 **8 天**；更远的时效不作数。不确定区间按模型样本外 RMSE 给出，**预报驱动自身的误差未单独传播**，真实风险可能落在区间之外。
4. **这是研究演示，不是官方预警**；停航、闭园等决定须以马来西亚气象局（MetMalaysia）与沙巴公园管理局发布为准。
